# 引き継ぎ資料 (handoff)

このディレクトリには、チャット分割で実装を継続するための引き継ぎドキュメントが含まれます。

## ファイル構成

| ファイル | 用途 |
|---|---|
| `00_common.md` | **全チャット共通の基盤情報**。プロジェクト概要、設計判断、ディレクトリ構成、命名規則 |
| `01_data_prep.md` | **チャット1: データ準備** 用。CSV → records.json |
| `02_dify_execution.md` | **チャット2: Dify実行** 用。records.json → classifications.json |
| `03_result_output.md` | **チャット3: 結果出力** 用。両JSON → 最終CSV |

## チャット分割の構成

```
[CSV]
   ↓
┌─────────────────────────────────┐
│ チャット1: データ準備            │  ← 01_data_prep.md
│ split, zone_extractor 利用       │
└─────────────┬───────────────────┘
              ↓ 境界A: outputs/prepared_data/{timestamp}_records.json
              ↓
┌─────────────────────────────────┐
│ チャット2: Dify実行             │  ← 02_dify_execution.md
│ dify_client 利用                 │
└─────────────┬───────────────────┘
              ↓ 境界B: outputs/dify_results/{timestamp}_classifications.json
              ↓
┌─────────────────────────────────┐
│ チャット3: 結果出力             │  ← 03_result_output.md
│ derive_metrics, output_formatter │
│ (このチャットで新規実装)         │
└─────────────┬───────────────────┘
              ↓ outputs/final/{timestamp}_*.csv
              ↓
       Tableau / DB
```

## 新しいチャットを開始する際の手順

### 1. まず共通基盤を貼る

新チャットの **最初のメッセージ** に `00_common.md` の内容を貼り付けてください。これでプロジェクトの全体像、設計判断、ディレクトリ構成が伝わります。

### 2. 担当チャットの引き継ぎ資料を貼る

続けて、そのチャットが担当する範囲の引き継ぎ資料を貼ってください:

- データ準備チャット → `01_data_prep.md`
- Dify実行チャット → `02_dify_execution.md`
- 結果出力チャット → `03_result_output.md`

### 3. 必要なファイルをアップロード

各チャットで実際のコード実装を再生する場合、以下のいずれかが必要です:

- 既存コード一式 (`repair_failure_classifier/` ディレクトリ全体)
- または、必要モジュールだけ (例: チャット3なら `codes_loader.py`, `classification_codes.yaml` 等)

### 4. チャット間の引き継ぎタイミング

- チャット1 → チャット2: `{timestamp}_records.json` をチャット2に渡す (タイムスタンプを共有)
- チャット2 → チャット3: `{timestamp}_classifications.json` をチャット3に渡す
- チャット3 → 完成: `{timestamp}_*.csv` を Tableau や DB に取り込み

## 各チャットで守るべきルール

1. **既存テストを壊さない**: `pytest tests/` 全件パスを維持
2. **境界の入出力契約を守る**: スキーマ変更は要関係チャット合意
3. **{timestamp} を共有**: 同じパイプライン実行で同じタイムスタンプを使う
4. **重要判断は記録**: 引き継ぎ資料を更新

## 推奨運用

### 並行開発する場合

3つのチャットを並行して進める場合、依存関係に注意:

- チャット1 (データ準備) → 独立して進められる
- チャット2 (Dify実行) → チャット1の records.json スキーマが必要、Dify構築も必要
- チャット3 (結果出力) → 両者のスキーマが必要だが、サンプルデータで先行実装可能

### 段階的に進める場合 (推奨)

```
Step 1: チャット1だけ進める → records.json 出力まで完成
Step 2: チャット2を開始 → Dify構築 → 疎通確認 → classifications.json 出力
Step 3: チャット3を開始 → derive_metrics, output_formatter 実装
Step 4: 全体エンドツーエンド実行
```

## 引き継ぎ時のFAQ

### Q: 新チャットで「過去の議論を知らない」状態になりませんか?

A: 引き継ぎ資料 (`00_common.md` の「過去の重要なやり取り抜粋」セクション) で主要な設計判断と理由を整理しています。新チャットでは、これを読めば「なぜこの設計か」を理解できます。

### Q: スキーマ変更が必要になったらどうしますか?

A: 影響を受ける関係チャットで合意してから、関連する引き継ぎ資料 (`01_*.md`, `02_*.md`, `03_*.md`) のスキーマ部分を同期更新してください。境界A・Bの契約はチャット間の重要なインタフェースです。

### Q: 既存の Notebook (02_pilot_run.ipynb) はどのチャットで触るべきですか?

A: 02_pilot_run.ipynb は **チャット1とチャット2にまたがる**Notebookです。引き継ぎ後は:

- チャット1: 「records.json 出力まで」のNotebookとして拡張 or 別Notebook作成
- チャット2: 「records.json 読込から classifications.json 出力まで」のNotebookとして整理

理想的には、責務ごとに Notebook を分けるとクリーン。

### Q: チャット間で {timestamp} はどう共有しますか?

A: チャット1の作業完了時に「`outputs/prepared_data/20260506_143012_records.json` を生成しました」のように具体的なパスを共有。チャット2/3では同じ `20260506_143012` を使ってファイルパスを構築します。

### Q: 全部1つのチャットで進めるのと比べてどんなメリットがありますか?

A:
- 各チャットのコンテキストが軽くなり、応答精度が上がる
- 領域ごとに集中できる (データ加工 / API呼出 / 集計 が混ざらない)
- 後から見返しやすい (どこで何を議論したか明確)
- チームでの分担運用がしやすくなる
